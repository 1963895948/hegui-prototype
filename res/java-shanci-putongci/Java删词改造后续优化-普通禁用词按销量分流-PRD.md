### 一、业务背景和价值

#### 1.业务背景

Java 删词改造后的流程以《QQJS-35837：java删词改造流程确认（责任人：袁效国）》为准，原文不改：

https://alidocs.dingtalk.com/i/nodes/Gl6Pm2Db8D3kB579t9yBwbnzJxLq0Ee4

原流程图里，数据在「是否禁售 = 否」且走到「普通禁用词」分支后，按近 365 天销量分流：

- 销量大于等于 0：进入人工处理（删词待处理列表）
- 销量小于 0：提交删词队列

销量为 0 的普通禁用词因此会进入销售人工列表。这类链接没有近 365 天销量，仍占用人工删词、保留、删 listing 的处理量。本次只调整这一处判断，其余分支保持原流程。

#### 2.业务价值

- 近 365 天销量为 0 的普通禁用词改为技术处理（提交删词队列），减少销售在删词待处理列表中的无效人工量。
- 近 365 天销量大于 0 的普通禁用词仍由销售人工处理，避免自动删词影响有销量链接。
- 高危禁用词、商标词、SKU 禁售、店铺状态、每日删 listing 额度等规则不变，控制改动范围。

- 业务若要求提升优先级，待补充。

### 二、需求描述

#### 1. 需求背景

基线文档 QQJS-35837 已经定义 Java 删词的状态回写、判断条件和删词处理列表。本次是该流程的后续优化，只改「普通禁用词」分支上的销量判断，不改写基线文档。

#### 2. 目标用户

- 销售：处理进入删词待处理列表的有销量普通禁用词。
- 侵权禁售 / 系统：对无销量普通禁用词提交删词队列。
- 高级主管：仍只处理基线文档中的「确认删除 listing」，本次不新增权限。

#### 3. 核心目标

普通禁用词走到原流程对应分支时：

- 近 365 天销量 **大于 0** → 人工处理
- 近 365 天销量 **小于等于 0** → 技术处理

#### 4. 功能范围

做：

- 仅调整原流程图「普通禁用词 → 近 365 天销量」这一判断的去向。
- 人工处理仍进入删词待处理列表；技术处理仍提交删词队列。
- 状态回写仍使用基线文档的颜色和状态码。
- 新原型只展示本分流，不替换旧删词列表原型。

不做：

- 不修改 QQJS-35837 原文。
- 不改高危禁用词、商标词分支。
- 不改「是否禁售 = 是」后的提交 listing 删除队列，以及每天 5000 条额度、超额转人工、钉钉通知。
- 不改店铺是否正常、近 365 天销量小于等于 0 且无 FBA 链接、回扫敏感词、保留按钮的适用类型。
- 不改删词处理列表的查询条件、字段、批量操作和日志字段。
- 已在删词待处理列表中的历史数据是否按新规则改派：**待补充**。本期默认只作用于新进入该分支的数据。

### 三、功能详细需求

#### 1 功能模块一：普通禁用词销量分流

##### 1.1 页面入口

无新菜单。分流发生在 Java 删词流程内部。

销售仍从基线文档中的删词处理列表处理「人工处理」数据。技术处理不进入该列表，进入删词队列。

原型（新建，不覆盖旧原型）：

https://1963895948.github.io/xiaoguo/qinquan-jinshou/java-shanci-putongci/index.html

##### 1.2 前置条件

同时满足才进入本规则：

1. 数据已按 QQJS-35837 进入 Java 删词流程。
2. 「是否禁售」判定为否。禁售为是时，仍走原「提交 listing 删除队列（当天 5000 次后停用）」分支。
3. 「商标词、禁用词是否高危」判定为普通禁用词。高危禁用词、商标词仍走原分支。
4. 同一 listing 同时命中高危禁用词或商标词时，按原流程走高危 / 商标词分支，不按本规则改道。

销量口径：沿用该节点已有字段 **近 365 天销量**。不改用近 30 天销量、近 90 天销量或订单数。近 90 天销量仍只用于基线文档里「删 listing」按钮的限制，与本次分流无关。

##### 1.3 功能描述

**与原流程的差异**

| 近 365 天销量 | QQJS-35837 原流程图 | 本需求 |
|---|---|---|
| 大于 0 | 人工处理（删词待处理列表） | 不变，人工处理 |
| 等于 0 | 人工处理（原分支文案为销量大于等于 0） | 改为技术处理 |
| 小于 0 | 提交删词队列 | 不变，技术处理 |

**主流程**

1. 触发：listing 在原流程走到「普通禁用词」节点。
2. 读取该 listing 的近 365 天销量。
3. 销量大于 0：
   - 动作：进入人工处理，落入删词待处理列表。
   - 结果：销售可按基线文档操作确认删词、删除 listing、保留（仅普通禁用词可保留）。
   - 回写：结束在人工节点时，向产品商标&禁售词检索系统回写「人工」状态 5。流程未结束、节点为白色时保持「未删」。
4. 销量小于等于 0：
   - 动作：技术处理，提交删词队列，不进入删词待处理列表。
   - 结果：由删词队列执行删词。
   - 回写：提交成功等待结果时为未删中的 4（已提交待确认）或 9（处理中）；删词成功为已删 1；队列返回失败为失败 8。处理失败（含店铺授权问题）仍为失败 3，并按原流程重试。

**人工处理之后（沿用基线，本次不改）**

删词待处理列表中的确认删词、删除 listing、高级主管确认删除 listing、保留、每天回扫文案、日志，全部以 QQJS-35837 为准。

**技术处理之后（沿用基线队列）**

提交删词队列后的成功、失败、重试，与原流程图「提交删词队列 → 是否删除成功」一致。成功则按原流程回扫是否还有敏感词；失败按原失败分支处理。

**异常流程**

| 场景 | 处理 |
|---|---|
| 近 365 天销量为空、null，或取数失败 | **待补充**。本期不得把空值当成 0 自动提交删词队列。 |
| 提交删词队列失败 | 沿用基线：失败 3 后续重试；队列返回失败为 8。不因本次优化新增重试次数。 |
| 同一 listing 重复进入本分支 | 沿用基线幂等。已在删词队列或已有终态的数据如何防重复提交：**待补充**。 |
| 处理过程中销量发生变化 | 以进入本判断节点时读取到的近 365 天销量为准。进入之后销量再变化，不自动改派。 |

**边界场景**

| 场景 | 预期 |
|---|---|
| 普通禁用词，近 365 天销量 = 1 | 人工处理 |
| 普通禁用词，近 365 天销量 = 0 | 技术处理（本次变化点） |
| 普通禁用词，近 365 天销量小于 0 | 技术处理 |
| 仅高危禁用词或仅商标词 | 不走本规则，原分支不变 |
| 同时有普通禁用词和高危禁用词或商标词 | 走原高危 / 商标词分支 |
| SKU 在对应平台站点禁售 | 走原禁售删 listing 分支，不受本销量规则影响 |
| 店铺异常 | 仍走原「是否正常店铺」之后的分支；本规则不替代店铺判断 |
| 已在人工列表中的历史数据 | 本期不自动改派。是否回刷待补充 |

#### 2 功能模块二：原型

##### 2.1 页面入口

独立原型页面，不挂到现网菜单。地址见 1.1。

##### 2.2 前置条件

原型使用示例数据，不接生产接口。

##### 2.3 功能描述

原型需要让人直接看清分流结果，至少包含：

1. 规则说明：标出本次只改普通禁用词的销量判断。
2. 分流试算：选择「仅普通禁用词 / 含高危或商标词 / SKU 禁售」，输入近 365 天销量，展示去向。
3. 结果列表：至少有一条销量大于 0 的普通禁用词进入人工，一条销量等于 0 的普通禁用词进入技术处理，一条高危或商标词标记为仍走原流程。

列表上的确认删词、删 listing、保留若做出交互，行为与基线一致，且不能把销量小于等于 0 的普通禁用词放进人工列表。

### 四、风险描述

- 销量等于 0 的普通禁用词改为自动提交删词队列。若业务仍希望人工决定保留，会直接进入删词，存在误删文案的风险。
- 销量口径固定为近 365 天销量。若业务实际指近 30 天或近 90 天，分流会偏。口径待业务确认前，开发按近 365 天销量实现。
- 历史人工列表不自动改派时，同一类「销量 = 0 的普通禁用词」会短期同时存在于人工列表和删词队列。
- 空销量若被当成 0，会把取数失败的数据自动删词。空值规则未补充前，不允许按 0 处理。

### 五、验收标准

#### 1 验收时间

默认：**需求上线后 5 个工作日内**验收完成。

#### 2 服务验收标准

1. 输入一条仅含普通禁用词、未禁售、近 365 天销量 = 5 的 listing，进入「普通禁用词」分支后，进入删词待处理列表，不提交删词队列；流程结束在人工节点时，检索系统状态为人工（5）。
2. 输入一条仅含普通禁用词、未禁售、近 365 天销量 = 0 的 listing，提交删词队列，不进入删词待处理列表。
3. 输入一条仅含普通禁用词、未禁售、近 365 天销量 = 1 的 listing，结果与第 1 条相同，进入人工处理。
4. 输入一条高危禁用词或商标词 listing，分流结果与 QQJS-35837 原分支一致，不因为销量小于等于 0 改走本需求的技术处理。
5. 输入一条 SKU 禁售 listing，仍走原提交 listing 删除队列分支，不受本销量规则影响。
6. 删词待处理列表中，销量大于 0 的普通禁用词仍可按基线执行确认删词、删除 listing、保留；高级主管确认删除 listing 的权限与状态限制不变。
7. 对照 QQJS-35837 原文，该文档内容与本次上线前一致，未被本需求改写。
8. 近 365 天销量为空时的处理，在「待补充」关闭前不按销量 = 0 提交删词队列。
